# codex-sns1

旧Twitter風SNSをCodexで開発するプロジェクトです。
トップページでSQLiteの投稿を取得して表示し、投稿モーダルから本文を保存できます（Issue #2・#3）。

PC向けの3カラム構成です。投稿本文・投稿者・表示日時・各件数を表示し、投稿一覧と投稿作成以外の機能は「準備中」で操作できません。
対応画面幅は1024px以上です。スマートフォン専用レイアウトはなく、それ未満では横スクロールします。

## 前提環境

- Node.js 22.12以降の22系、または24系
- npm（Node.jsに同梱）
- uvとPython 3.12系（uvが対応するPythonを用意できます）

依存の直接バージョンとロックファイルをGitで管理しています。

## 最初の起動

リポジトリのルートから、バックエンドを準備します。

```sh
cd backend
uv sync --locked
uv run --locked alembic upgrade head
uv run --locked python -m sns.seed
uv run --locked uvicorn sns.main:app --reload --host 127.0.0.1 --port 8000
```

- `uv sync --locked`：依存を導入し、`src/sns` を開発用パッケージとしてインストールします。
- `alembic upgrade head`：`backend/data/sns.db` に投稿テーブルと適用履歴を作成します。適用済みなら変更しません。
- `python -m sns.seed`：3件の確認用投稿を投入します。同じIDはスキップし、既存値を上書きしません。
- `uvicorn`：APIサーバーを起動します。起動するだけではDBの作成や初期データ投入を行いません。

別のターミナルでフロントエンドを起動します。

```sh
cd frontend
npm ci
npm run dev
```

[トップページ](http://127.0.0.1:5173/)を開くと、投稿が新しい順（同じ投稿日時なら投稿IDの大きい順）に表示されます。
停止するには、それぞれのターミナルで `Ctrl+C` を押します。ポートが使用中なら既存サーバーを確認してください。

## APIとデータ

| 接続先                                        | 用途                       |
| --------------------------------------------- | -------------------------- |
| ブラウザの `GET /api/posts`                   | Viteを経由した投稿一覧取得 |
| バックエンドの `GET /posts`                   | 認証なしの投稿一覧取得     |
| ブラウザの `POST /api/posts`                  | Viteを経由した投稿作成     |
| バックエンドの `POST /posts`                  | 認証なしの投稿作成         |
| [APIドキュメント](http://127.0.0.1:8000/docs) | FastAPIが生成するAPI仕様   |

一覧取得の正常時はPostの8項目を持つJSON配列を返します。0件は200と `[]`、取得失敗は500と `POST_LIST_FETCH_FAILED` です。未来の投稿日時が1件でもあれば一覧全体を失敗として扱います。
200・500応答はキャッシュしません。投稿を閲覧しても件数や本文は変更されません。投稿作成は既存の投稿テーブルへ1件を追加します。

日時はUTCで保存し、表示用の文字列をAPIで計算します。1週間未満は「○分」「○時間」「○日」、1週間以上は日本時間の日付です。
表示日時は再取得時に更新され、画面を開いたままの自動更新は行いません。

既存のVite設定で `/api/posts` をバックエンドの `/posts` に転送します。開発時のブラウザには同一オリジンの接続に見えます。
この転送は開発サーバー用です。本番の配信・転送構成は別途必要です。

接続確認用の `GET /`・`GET /health` と旧DB初期化コードは廃止しました。既存の `sample.db` ファイルは削除・移行しません。

## フロントエンドの読み方

- `frontend/src/App.jsx`：ホーム画面と表示部品を定義します。`LeftSidebar`、`Timeline`、`PostCard`、`RightSidebar` がそれぞれ画面の一部分を担当します。
- `useState` は読み込み状態・投稿データ・モーダルの状態を保持します。`useEffect` は初回表示・再試行に合わせてAPIを呼びます。状態が変わるとReactが必要な部分を描き直します。
- `frontend/src/style.css`：3カラムの配置、青い強調色、余白、投稿の区切り線を設定します。
- JSXの `{post.body}` は本文を文字列として扱うため、投稿内のHTMLを実行しません。CSSの `white-space: pre-wrap` で改行を保持します。

取得中・0件・失敗を別の状態として扱い、失敗時には再試行できます。5秒でタイムアウトし、再試行中の重複操作や画面離脱後の応答反映を防ぎます。再取得中・取得失敗時も表示済み投稿を保持します。

## バックエンドの構成

| 配置                          | 役割                                                    |
| ----------------------------- | ------------------------------------------------------- |
| `backend/src/sns/main.py`     | FastAPIの起点、HTTP応答とエラー変換                     |
| `backend/src/sns/database.py` | 接続先・閲覧用/投稿用接続・モデルのBase                 |
| `backend/src/sns/models.py`   | 保存用のPostRecordとDB制約                              |
| `backend/src/sns/schemas.py`  | 入力用PostCreate・応答用Post/CreatedPost・ErrorResponse |
| `backend/src/sns/posts.py`    | 投稿作成・一覧取得・UTC復元・表示日時の算出             |
| `backend/src/sns/seed.py`     | シード検証・投入・重複スキップ                          |
| `backend/migrations/`         | Alembicの移行処理と適用履歴                             |
| `backend/tests/`              | 一時DBを使用する自動テスト                              |

`src` はソースの置き場所で、Pythonでimportするパッケージ名は `sns` です。
SQLiteの日時保存値はTEXTで、SQLAlchemyがPythonのdatetimeへ変換します。保存時はUTCに統一し、取得時にUTCとして復元します。

## コマンドと確認

```sh
# backend/ 内
uv run --locked pytest -q
uv run --locked ruff check src migrations tests
uv run --locked ruff format --check src migrations tests
uv run --locked alembic current
uv run --locked alembic check

# frontend/ 内
npm test
npm run build
```

バックエンドのテストは専用の一時DBを使います。開発中の `sns.db` や `sample.db` は変更しません。
別のDBを手動確認する場合は、各バックエンドコマンドに環境変数 `SNS_DATABASE_PATH` で絶対パスを指定します。API・Alembic・シードは同じ設定を使います。

DBファイル・ジャーナルは `backend/data/` に保存され、Git管理対象外です。準備処理はAPIを停止して単独で実行してください。
初回移行のdowngradeは投稿テーブルを削除するため、通常の再実行や復旧には使用しません。

## 表示されないとき

- 「投稿一覧を取得できませんでした。」：APIが起動しているか、マイグレーションが完了しているか確認してください。DBがない場合も、空一覧を返さず失敗します。
- 「まだ投稿がありません」：取得は成功しています。初期データが必要ならAPI停止後にシードを投入してください。
- バックエンドを停止すると失敗表示になり、再起動後に「再試行」で復旧できます。

## 設計書

`docs/detail_design/` に入出力・ロジック・API・データベース設計書を保存しています。
投稿編集・削除・返信・リツイート・いいね操作・検索・フォローは実装対象外です。

## 本文を投稿する

1. 左サイドバーまたは中央の「投稿する」を押します。
2. モーダルへ本文を入力し、「投稿する」で送信します。Enterは改行です。
3. 保存に成功するとモーダルが閉じ、新規投稿が先頭に表示され、「投稿しました」と通知されます。再読み込み後もDBから取得できます。

- 投稿者は固定の「自分」、投稿日時はサーバーの受付時刻、各件数は0です。ログインは不要です。
- 本文は1〜280 Unicodeコードポイントです。絵文字や結合文字の見た目と文字数は一致しない場合があります。改行・前後の空白を保持し、空欄・指定空白のみの投稿を拒否します。
- 送信中は本文・閉じる・再送信を無効にします。Escや閉じるで入力を破棄する際は確認し、取り消すと本文を保持して入力へ戻ります。背景クリックでは閉じません。
- 失敗時は本文を保持し、手動で再試行できます。通信断・5秒超過・不正応答では保存済みの場合があるため、一覧確認を案内します。自動再送信や別要求の重複防止はありません。
- 「一覧を確認する」は入力の破棄確認後にホームで再取得します。下書き保存・画像添付・公開範囲は対象外です。

ブラウザの `POST /api/posts` はVite経由で `POST /posts` へ転送します。JSONは `{"body": "投稿本文"}` のみです。成功は201と保存した7項目を返し、`displayed_at` は含めません。画面側で「たった今」を補ってReactの一覧状態へ追加するため、ページ再読み込みや直後のGETは不要です。GETと競合しても投稿IDで統合し、再取得後はGETの表示日時を使用します。

入力不正は422・`POST_VALIDATION_FAILED`、保存失敗は500・`POST_CREATE_FAILED` です。`code`・`message` の固定JSONと `Cache-Control: no-store` を返し、投稿本文・例外の詳細をエラー応答やログへ含めません。

DBスキーマの追加変更はありません。初回セットアップと同じAlembic適用済みDBを利用し、投稿用には `mode=rw`、一覧用には `mode=ro` の接続を使います。DBがない・未移行の場合は失敗し、APIでは自動初期化しません。シード投入は投稿作成の前提ではありません。

フロントエンドは `PostComposer.jsx` が入力・送信・フォーカスを、`posts.js` が入力検証と一覧の統合を担当します。バックエンドは `PostCreate` が入力、`CreatedPost` が作成応答、`Post` が一覧応答です。1投稿を1トランザクションで保存し、応答のJSON化をコミット前に検証してから201を返します。

## 投稿機能の検証

自動テストは上記のpytest・Vitestで実行できます。バックエンドは一時DBを使って文字数境界・不正入力・7項目の応答・保存値・再接続後の取得・失敗時のロールバックと接続解放を確認します。画面は送信連打・タイムアウト・遅延応答・一覧取得との競合・入力保持・破棄確認・フォーカスを確認します。

実ブラウザでも開発用DBとは別の一時DBを使い、両方の入口、Tab/Shift+Tab、連続Escの取消、背景操作禁止、投稿後のホーム反映・再読み込み後の表示、保存失敗後の手動再試行を確認しました。通信タイムアウト・遅延応答の制御は画面の自動テストで確認しています。
