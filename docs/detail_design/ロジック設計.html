ステータス 設計確定（Issue #2実装済み、Issue #3実装済み）

Issue #2の投稿一覧・初回移行・シードと、Issue #3の投稿モーダル・投稿作成APIを実装済み。POSTはCreatedPostの7項目、GETはdisplayed_atを含むPostの8項目を返す。実装と検証の範囲は末尾の確認結果に記載する。

対象範囲と設計の前提

ホームSCR-001（URL：/）の投稿一覧ITEM-003と、投稿モーダルSCR-002を対象とする。FUN・PRG・PRC等のIDは本書で管理する設計上のID。各図は処理仕様を示し、実装状況と検証結果は冒頭および末尾で管理する。

閲覧処理は保存済み投稿の参照のみとし、DBへのINSERT・UPDATE・DELETEを行わない。Issue #3の投稿作成はFUN-003として追加する。編集・削除は対象外。左右のサイドバー（COM-001・COM-002）の検索・通知・トレンド・おすすめなどは準備中の操作不可表示とし、本書では投稿一覧の処理に含めない。残る未決事項を14章にまとめる。

Postの属性とAPIでの型

項目 属性名（lower_snake_case） クラスの型 JSONの型 内容

displayed_at：表示日時の算出

API処理で現在時刻nowを1回取得し、各Postについて 経過秒数 = now - posted_at を求める。DBのposted_atはUTCとして復元してから比較する。同じ応答内ではnowを共有し、時差を含む同じ時間軸で比較する。1日は24時間、1週間は7日（604800秒）とする。

経過時間 displayed_atの値 例
1分未満 たった今 0〜59秒 → たった今
1分以上・1時間未満 整数の分数 + 分（端数切り捨て） 120秒 → 2分
1時間以上・1日未満 整数の時間数 + 時間（端数切り捨て） 7200秒 → 2時間
1日以上・1週間未満 整数の日数 + 日（端数切り捨て） 172800秒 → 2日
1週間以上 投稿日時をAsia/Tokyoへ変換し、yyyy/mm/dd形式に整形 2026年10月1日の投稿 → 2026/10/01

算出したdisplayed_atは応答時の値とし、DBの更新は行わない。画面を開いたままの自動再計算は今回の対象外。日付表示はAsia/Tokyo（JST、UTC+09:00）とする。posted_atが現在時刻nowを超える行が1件でもあれば、ERR-001として一覧取得全体をHTTP 500・POST_LIST_FETCH_FAILEDにする。未来の行の除外や相対表示の補正は行わない。posted_at == nowは正常とする。接続確認用の旧モデル・APIは削除し、PostRecordとPostを使用する。
